# Cluster definitions

Every email gets one cluster from this list. The cluster characterizes the *relationship + intent* of the thread, not the content. Pick from the list below; if no cluster cleanly applies, use the reserved "Needs Review" cluster at the end.

## Cluster 1 — Longtime friends

1:1 personal correspondence with someone you know well. First-name basis, references shared life, no business angle. Distinguish from coaching prospects (cluster N) and historical friends (cluster M).

**Default rating:** 7

**Example signals:**
- First-name-only display name
- "Hey [name]" / "Hi friend" opening
- References to shared events or mutual friends
- No subject prefix patterns; mixed lengths

## Cluster 2 — Family

Blood family or in-laws. The most-protected cluster — auto-rates to 9.

**Default rating:** 9

**Example signals:**
- Sender's display name matches a family member
- Sender's domain matches a family member's known address
- Body references "mom" / "dad" / spouse name / etc.

## Cluster 3 — Newsletters / lists

Industry / professional newsletters that you read selectively. The Phase 2 content scorer decides whether any specific issue surfaces.

**Default rating:** 1

**Example signals:**
- List-unsubscribe header present
- Sender like `news@*` / `weekly@*` / `digest@*`
- Body has a "view this email in your browser" link
- Body has a "you're receiving this because..." block

# Pre-classification auto-rules

Apply these before the LLM runs to short-circuit obvious cases:

- Sender matches `noreply@*` / `do-not-reply@*` / `notifications@*` AND body is system-templated → transactional cluster (or newsletter, if list-unsubscribe header present).
- List-unsubscribe header present AND sender is not in your contacts → newsletter cluster.
- The owner is sender AND every recipient is one of `me_addresses` → self-filing cluster.
- Subject starts with `[<known-list-name>]` → affinity-group / list cluster.
- Sender display name matches a row in `priority_friends.md` → set the `priority_friend` flag (overrides cluster default).

# Disambiguation rules

Common confusions (calibrate as you see mis-classifications):

- **Vendor pre-sale vs vendor support:** a question about whether to BUY is pre-sale. A question after buying is support.
- **Cold pitch vs newsletter:** a one-off unsolicited message from an unknown sender is cold pitch. A recurring same-from-address message is newsletter.
- **Prospect intro vs cold pitch:** an intro via a mutual contact is prospect intro. Direct outreach from a stranger is cold pitch.
- **Longtime friend vs occasional friend:** ≥3 exchanges in last 6 months = longtime. Less = occasional.
